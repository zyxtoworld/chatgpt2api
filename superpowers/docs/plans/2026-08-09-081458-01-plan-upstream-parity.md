# 上游协议、ccLoad 导入与官方接口一致性

**Goal:** 依据当前权威上游与官方接口证据，为现有单一应用补齐 Responses WebSocket、ccLoad OAuth 导入、工具/搜索参数及 Chat/Responses/Images 合同，并只吸收官方 issues 中可复现且有利的修复。
**Why planning is required:** 目标同时改变公开 API、OAuth 凭据流、长连接生命周期和唯一生产前端，属于跨系统与敏感凭据高风险变更。
**Acceptance:** 每个显式目标均有来源证据、公共边界红绿测试和当前工作树实现；凭据不进入日志/公开配置；WebSocket 认证、串行回合和资源关闭可复现；ccLoad 导入可在假服务上端到端完成；Chat/Responses/Images 与已确认官方字段一致；选取的 issues 有对应回归证据；对用户提供 SSH 主机只读定位高请求量卡顿，不做任何远端 mutation；纯本地后端与前端检查通过，真实账号/公网兼容性单独列为 missing。

### Outcome 1: 建立上游与本地能力矩阵
- Work: 固定当前 HEAD/dirty tree；记录 basketikun/chatgpt2api、caidaoli/ccLoad 预览版及 OpenAI 官方 Responses 文档的当前 revision/URL；逐项映射 WebSocket、OAuth 凭据、工具、搜索、流式 usage、Chat/Responses/Images 字段到本地调用链。
- Risks/open questions: ChatGPT 网页 `/backend-api/conversation` 没有公开协议文档；不得把 Codex OAuth `/backend-api/codex/responses` 的原生 WS 能力无证据套到 ChatGPT token。公开前端抓取若被 403，只报告该证据缺口。
- Verify: 只读 GitHub API/clone、OpenAI Docs 页面、`rg` 调用链和本计划中的 requirement-to-evidence 记录。

### Outcome 2: Responses WebSocket 长连接
- Work: 在现有 `/v1/responses` 同路径增加认证 WebSocket；所有普通文本、图片、函数工具和网页搜索回合优先使用 Codex 原生 `/backend-api/codex/responses` WebSocket，单连接串行复用并在当前连接内校验最近 `previous_response_id`；没有可用 Codex OAuth 时普通回合继续使用既有 HTTP/SSE 生成器。对尚未发送请求的瞬时握手失败按当前 Codex 客户端执行初次加两次有界连接尝试（200ms/400ms），耗尽后启用会话级粘性 HTTP 回退；HTTP 426 明确表示不支持升级，立即回退而不等待。除单连接 16MiB 与 64 连接上限外，对实际持久 transcript 设置进程级 128MiB 聚合预算，按 session 原子替换占用并在失败、关闭或 GC 时释放。
- Risks/open questions: 仅在账号选择/握手失败且请求尚未发送时重试或回退 HTTP/SSE；`generate:false` 预热不回退，发送后的异常禁止自动重放。握手日志只记录尝试次数、等待时间和 HTTP 状态等结构化元数据，不记录异常正文、URL 凭据或 token。预算不足不能把已成功的当前响应改成失败；清除该 session 的可重放状态，并在客户端尝试用对应 response id 续接时返回固定容量错误。连接内 transcript 有界且关闭即释放，不持久化输入、输出或 token；账号或传输切换时关闭旧上游连接并重建受控 transcript。
- Verify: TestClient 与上游连接假体覆盖认证、多回合复用、previous_response_id、工具结果续接、瞬时握手失败后成功、三次耗尽粘性回退、426 立即回退、发送后失败、错误投影、账号切换和断开清理；共享小预算的真实多 Session 合同覆盖聚合拒绝、原响应保留、续接容量错误及 fail/close/GC 释放；相关 Responses/认证测试、编译与 diff-check。
