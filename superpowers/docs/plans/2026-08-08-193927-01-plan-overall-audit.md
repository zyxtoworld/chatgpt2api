# Overall bug audit and self-test

**Goal:** 审计当前工作树的高风险输入与任务状态路径，修复已证实的根因，并用可复现的本地证据收口。
**Why planning is required:** 本次涉及 SSRF 防护、认证凭据生命周期和公开 API 合同，属于高风险安全与公共行为变更。
**Acceptance:** 当前 diff 无未审计的高风险回归；纯本地测试和编译检查通过；外部服务、缺失运行时与现有警告单独报告。

### Outcome 1: 审计远程输入与敏感状态流
- Work: 检查用户可控 URL 的所有抓取入口、重定向/DNS 边界、图片任务恢复凭据的内存/落盘/日志路径，并统一 Chat/Responses data URL 的 MIME、base64 和大小约束。
- Risks/open questions: 若发现新的用户可控网络出口，必须先以无网络负测确认根因再做最小修复。
- Verify: `rg -n "requests\\.(get|post)|allow_redirects|urlopen|access_token|resume_credentials" api services utils test`

### Outcome 2: 核对当前改动与行为覆盖
- Work: 检查工作树 diff、重复定义、测试隔离和文档/前端合同是否与单一 App Router 一致。
- Risks/open questions: 不创建第二套 UI 或版本化前端路径；不暴露配置密钥。
- Verify: `git diff --check`；`python -m compileall -q api services utils test main.py scripts`

### Outcome 3: 运行锁定环境中的本地证据
- Work: 使用已有 uv 锁定环境运行 collection、focused 和纯本地测试；不执行真实外网/账号测试。
- Risks/open questions: Bun 和 node_modules 缺失时仅记录前端检查 missing；外部 HTTP 测试单独记录，不推断源码结论。
- Verify: `uv sync --locked`；`pytest --collect-only -q`；纯本地测试集和 focused 测试集。

### Outcome 4: 最终状态与未覆盖项
- Work: 复查最终 diff、工作树、HEAD/remote，按源码、文档、运行环境、外部上游分类报告。
- Risks/open questions: 不能把未运行的外部集成测试写成通过，也不能把 SQLAlchemy deprecation warning 写成零警告。
- Verify: `git status --short --branch`；`git diff --stat`；进程残留检查。

### Outcome 5: 认证与公开错误合同复核

- Risks/open questions: 不改变既有鉴权语义，不联网调用真实账号或上游，不制造第二套前端路径。
- Verify: 认证/API focused 负测；`git diff --check`；锁定环境中的相关测试与编译检查。
